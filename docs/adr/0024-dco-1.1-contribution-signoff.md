# ADR-0024: Developer Certificate of Origin 1.1 Contribution Sign-Off

- **Status:** Proposed
- **Date:** 2026-09-15
- **Decision area:** Governance / Licensing / Contributor Readiness
- **Supersedes:** None
- **Related:** ADR-0003, `CONTRIBUTOR_PROTECTION_AND_ATTRIBUTION.md`

## Context

OpenBook is transitioning from an engineering-complete Gate 8 baseline toward public and multi-stakeholder contribution readiness. The project is licensed under Apache License 2.0 and its existing contributor-protection documentation states that contributors retain copyright in original material unless they separately transfer it under a written agreement.

The project therefore needs an explicit inbound contribution mechanism that establishes provenance and contributor authorization without unnecessarily transferring contributor copyright or creating a high-friction legal onboarding process.

Two principal mechanisms were considered:

1. **Contributor License Agreement (CLA):** a separate contractual agreement, potentially requiring signature and identity tracking.
2. **Developer Certificate of Origin (DCO) 1.1:** a commit-level certification recorded through a `Signed-off-by:` trailer.

The contributor-readiness architecture review recommends DCO 1.1 because it preserves the project's Apache-2.0 contribution model while providing a lightweight, auditable provenance mechanism.

## Decision

OpenBook will adopt the **Developer Certificate of Origin (DCO), Version 1.1**, as its contribution sign-off mechanism.

A contributor submitting a change for inclusion in OpenBook must certify the contribution by adding a valid `Signed-off-by:` trailer to each commit covered by the project's contribution policy. The sign-off must use the contributor's real name and email identity as required by the DCO and must not be fabricated or supplied on behalf of another person.

The project will use the DCO as a provenance and authorization mechanism; it does **not** constitute a copyright assignment to SanMitra Tech Solutions.

Contributions accepted into OpenBook remain subject to the Apache License 2.0 contribution terms and the project's existing contributor-protection policy.

## Rationale

### 1. Alignment with Apache-2.0

Apache-2.0 already establishes the licensing framework for submitted contributions. DCO sign-off adds an explicit contributor certification concerning the contributor's right to submit the work without requiring a separate copyright-transfer agreement.

### 2. Contributor ownership

DCO adoption is consistent with the project's existing position that contributors retain copyright in original material unless they separately transfer it through a written agreement.

### 3. Low contribution friction

A commit trailer is substantially simpler than requiring contributors to complete and maintain a separate CLA agreement. This is especially important for OpenBook because expected contributions include code, documentation, translations, accessibility improvements, sample content, and other non-code contributions.

### 4. Auditable provenance

A `Signed-off-by:` trailer creates a durable, repository-visible record that can be checked automatically in pull-request CI.

## Scope

This decision applies to contributions submitted to the OpenBook repository for inclusion in the project, including code, documentation, tests, configuration, examples, translations, and other copyrightable project materials.

The exact CI implementation, GitHub workflow, pull-request template wording, contributor documentation changes, and exception handling are implementation details to be defined in the subsequent contributor-readiness implementation work. This ADR does not itself authorize those implementation changes.

## Enforcement direction

Once implementation is separately authorized, OpenBook should enforce DCO compliance through a required pull-request check that verifies the commits introduced by the pull request contain valid `Signed-off-by:` trailers.

The implementation must:

- fail closed when a required sign-off is absent or malformed;
- avoid treating an arbitrary text occurrence as sufficient certification;
- report the offending commit(s) clearly to the contributor;
- document how contributors can amend or recreate commits with sign-off; and
- integrate with the repository's existing required-check and pull-request governance without weakening other branch protections.

The implementation should not require a contributor to sign off another person's work or permit maintainers to silently add a sign-off on the contributor's behalf.

## Exceptions and non-goals

This ADR does not establish a blanket exception policy for historical commits, automated merge commits, release automation, or bot-authored commits. Those cases must be explicitly defined when the enforcement workflow is designed and reviewed.

This ADR does not:

- change the Apache License 2.0;
- assign contributor copyrights to SanMitra Tech Solutions;
- establish project stewardship or maintainer appointment rules;
- establish a Code of Conduct or security disclosure process;
- establish a dependency license allowlist or SBOM process; or
- declare OpenBook `CONTRIBUTOR-READY`.

Those subjects require separate governance decisions or implementation work.

## Consequences

### Positive

- Provides a clear and lightweight contribution provenance mechanism.
- Preserves contributor copyright ownership under the existing project policy.
- Fits naturally with Apache-2.0 licensing.
- Enables automated enforcement in pull requests.
- Reduces legal and administrative onboarding friction.

### Negative / trade-offs

- Contributors must understand and comply with commit sign-off requirements.
- Existing unsigned commits in a contributor's branch may require rewriting before a pull request can pass the DCO check.
- Automated and exceptional commit scenarios require explicit enforcement rules.
- DCO does not replace broader governance, security, licensing, or trademark policies.

## Acceptance criteria for this ADR

This ADR may move from **Proposed** to **Accepted** only after project-steward review confirms:

1. DCO 1.1 is the intended contribution mechanism for OpenBook.
2. Adoption does not transfer contributor copyright by itself.
3. The Apache-2.0 contribution model remains authoritative.
4. The implementation is separately authorized and will be enforced through repository CI without weakening existing branch protections.
