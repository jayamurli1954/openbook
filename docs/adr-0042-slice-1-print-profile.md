# ADR-0042 Slice 1: Print Profile in the PDF Engine — Implementation Proposal

- **Status:** In progress (this PR)
- **Date:** 2026-11-05
- **Parent architecture:** ADR-0042 — Print-Ready Paperback PDF Architecture, §2.1, §4 invariants 1–4 and 6–7, §7 Slice 1
- **Scope:** the PDF engine (`@openbook/pdf`) learns a print profile: trim size, mirrored margins, page numbers, no cover page, and a page limit. No desktop change (Slice 3), no picture check (Slice 2).
- **Implementation authorization:** Granted for this slice only; page numbers count from the title page (maintainer, 2026-11-05: "Count from title page")

## 1. Purpose

Today every PDF uses `DEFAULT_PDF_PROFILE` (A5, symmetric margins, no page numbers, a cover page when the book has a cover). This slice adds the print profile so the engine can produce the paperback interior that was built by hand for *Little Krishna's Wisdom*.

How the engine works today:

- `serializeBookToTypst(book, resolvedImages)` writes the page setup lines:
  - `#set page(paper: "a5", margin: (x: 1.75cm, y: 2.25cm))`;
  - then the optional cover page;
  - then the title page, then one section after another.
- `buildPdf(book, options)` resolves pictures, serializes, and compiles with Typst 0.15.1.
- `pdf.test.ts` covers the Typst source; rendered checks run where the Typst runtime is present (the CI Gate 6 job and locally).

## 2. Slice 1 objective

1. **Profile types** (`packages/pdf/src/print-profile.ts`):

   ```ts
   type PrintTrimId = "5x8" | "5.25x8" | "5.5x8.5" | "6x9" | "7x10" | "8x10" | "8.5x11" | "a5";
   interface PdfPrintProfile { kind: "print"; trim: PrintTrimId }
   type PdfProfile = { kind: "reading" } | PdfPrintProfile;
   const PRINT_TRIM_SIZES: readonly { id: PrintTrimId; label: string; widthIn: number; heightIn: number }[];
   ```

   - The labels are what the Export step shows later, e.g. "5.5 × 8.5 in" and "A5 (5.83 × 8.27 in)".
   - Unknown ids are refused with a structured error.

2. **Serializer:** `serializeBookToTypst(book, resolvedImages, profile = { kind: "reading" })`.

   - **Reading:** the output is unchanged, character for character.
   - **Print:**
     - `#set page(width: …in, height: …in, margin: (inside: 0.75in, outside: 0.5in, y: 2.25cm), footer: …)`, using the chosen trim size and mirrored margins.
     - The footer shows the page number, centred, in 9 pt body font, on every page except page 1 (the title page). Page numbers count from the title page (see §6).
     - No cover page, even when the book has a cover.
     - A page limit: a book over 700 pages fails to compile with "This book has more than 700 pages; paperback margins are only set for up to 700 pages." This is done inside the Typst source (a check on the final page count), so it needs no second pass.
     - Everything else (fonts, headings, pictures, captions, lesson boxes, the title page) is the same text as in the reading source.
   - The `// Generated by …` comment line names the profile, e.g. `(print, 5.5x8.5)`. Reading keeps its current line, so it stays byte-identical.

3. **Builder:** `PdfBuildOptions.profile?: PdfProfile`, passed to the serializer. Default is reading.

4. **Exports:** `PdfProfile`, `PdfPrintProfile`, `PrintTrimId`, and `PRINT_TRIM_SIZES` from `@openbook/pdf`.

5. **Tests:**

   **Source tests:**
   - Reading output is identical to the current engine for the existing fixtures (a fixed expected string, plus a check against a build of `main`).
   - Print source for each trim size has the page line, the footer, and no cover page when a cover is set.
   - English and Kannada books produce identical body text across the two kinds.
   - An unknown trim id is refused.

   **Rendered tests** (where the Typst runtime is present):
   - Every page is the trim size (5.5 × 8.5 and A5), read from each page's media box.
   - The cover page that the reading PDF has is left out.
   - Two builds are byte-identical.
   - A generated book over 700 pages fails with the plain message.
   - Page numbers and margins are not read back in CI: the package has no PDF text reader, and adding one is a dependency. The source tests pin them, and the real-book check measures them (§4).

## 2a. Implementation notes

- **Hanging punctuation.** Typst lets punctuation hang slightly into the margin when it justifies text. Measured on the real book, text reaches 0.68 in from the inside edge and 0.43 in from the outside edge. That is still well above KDP's no-bleed minimums: 0.375 in inside for 24–150 pages, and 0.25 in outside.
- **Page count changes with the margins.** The print text area is a little wider than the reading PDF's, so the real book has 69 pages instead of the 72 of the hand-built file. KDP's Standard colour needs at least 72 pages, so this matters for the maintainer's book (§7).

## 4. Acceptance criteria

- The reading PDF source is byte-identical to `main` for every fixture, checked against a build of `main`.
- The print PDF meets ADR-0042 invariants 2–4 in rendered tests: trim size on every page, numbers on pages 2…n, no cover page, margin floors, deterministic bytes, and the over-700 refusal.
- English and Kannada: same text, fonts, and lesson boxes in both kinds.
- **Real-book check (local, not committed):**
  - the maintainer's book built with `{ kind: "print", trim: "5.5x8.5" }`;
  - compared with the hand-built `Little_Krishnas_Wisdom_paperback_5.5x8.5.pdf`: page size, page count (72 ± a page or two, from the wider inside margin), numbers, and margins;
  - pages looked at.
- `npm test` for `@openbook/pdf`, the full repository, and CI pass; the diff stays within Slice 1.

## 6. Decision

**Decided 2026-11-05 by the maintainer: "Count from title page."** The options considered:


**Where should page 1 be?**

- **Recommended: count from the title page.** The title page is page 1 with the number hidden, so the first story starts on a low number such as 8. This is what your KDP paperback already uses, and it is the usual way for short books.
- **Alternative: start at 1 on the first chapter.** Pages before Story 1 (title, foreword, publisher's note) have no numbers, and Story 1 starts on page 1. Common in longer books, but the front pages then carry no numbers at all (Roman numerals stay out of scope).

## 7. Note for the maintainer's paperback

The book now comes out at 69 pages, and KDP's Standard colour needs at least 72. The live KDP paperback uses the hand-built 72-page file, so nothing changes there.

If a later edition is exported from OpenBook, the page count will matter. Either choose Premium colour, or let the book run a few pages longer: for example, start each story on a new page, or add pages such as a dedication. This slice does not pad pages.
